🎓 5-Minute Viva Presentation Script & Talking Points

Course Defense Guide
Step 1

Introduction & Problem Statement (1 Minute)

What to say: "Real-time multiplayer games stream high-frequency player movement packets over UDP (60 to 128 Hz). Conventional block ciphers like AES-128 add encryption overhead and force 16-byte block padding on small 8-byte game vectors, wasting network bandwidth. In AR-SPECK, we designed an Adaptive Round SPECK cipher with sensitivity-tiered encryption wrapped in an authenticated, replay-protected UDP protocol."

Step 2

ARX Cipher Core & Zero S-Box Architecture (1 Minute)

What to say: "SPECK is an ARX (Add-Rotate-XOR) cipher. It uses only three CPU operations: Modular Addition mod 232 for non-linear mixing, bitwise rotations (Rotate Right 8, Rotate Left 3) for linear bit diffusion, and XOR for key injection. Because SPECK uses zero lookup tables (S-Boxes), it eliminates cache-timing side-channel vulnerabilities."

Step 3

Sensitivity Tiering & Verify-Then-Decrypt Ordering (1 Minute)

What to say: "Packets are categorized into sensitivity tiers: TIER_LOW (position updates) uses reduced 12 SPECK rounds to save CPU cycles, while TIER_HIGH (score/items) uses standard 27 rounds for full security. Every packet carries a 21-byte wire format with an HMAC-SHA256 MAC. Crucially, the server enforces Verify-Then-Decrypt: if the MAC is invalid, decryption is skipped completely, preventing chosen-ciphertext attacks."

Step 4

64-Bit Sliding Window Replay Defense (1 Minute)

What to say: "UDP traffic can arrive out of order. A simple 'last seen counter' would drop valid reordered packets. Our server maintains a per-client 64-bit sliding window bitmap. Out-of-order packets inside the 64-sequence window are accepted, while genuine duplicate sequence numbers are detected instantly as replays and dropped."

Step 5

Live Web Demo & Measured Results (1 Minute)

What to show: Click the live simulation buttons on the Live Socket Control tab to demonstrate: (1) Position & Score packet encryption, (2) Ciphertext bit-flip detection (BAD_MAC drop), (3) Replay attack rejection, and (4) The 2.58× latency reduction table in Phase 6."

Expected Faculty Viva Questions & Exact Answers

Q1: Why does sensitivity tiering affect SPECK rounds but never the MAC?

Answer: The MAC provides integrity and authenticity for all packets. Reducing MAC strength would allow attackers to forge packets. Therefore, HMAC-SHA256 always executes at full strength, while round-count reduction is applied strictly to the cipher step for routine low-sensitivity payload data.

Q2: Does reducing SPECK rounds to T=12 compromise diffusion?

Answer: Our Phase 5 crypto measurements prove that at T=12 rounds, SPECK achieves near-ideal 50.05% avalanche diffusion (flipping 1 plaintext or key bit flips ~32 ciphertext bits) and passes NIST SP 800-22 Monobit Frequency and Runs randomness tests (p > 0.01).

Q3: Why use SPECK64 instead of AES-128 if AES hardware instructions exist?

Answer: AES requires a 16-byte block size. For an 8-byte game vector, AES forces 8 bytes of padding, doubling wire overhead. SPECK64 operates natively on 8-byte blocks without padding overhead, making it lighter over UDP network paths.
